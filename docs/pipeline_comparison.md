## Stage-by-stage comparison

| Stage | My previous pipeline | Swetha pipeline | Recommended SAR implementation |
|---|---|---|---|
| **Raw AVRO handling** | `find_participant_avro()` globs `data/{pid}/**/*.avro` recursively, sorts by the UNIX-second integer embedded in the filename. One streamed pass per participant, one open handle per sensor. | `convert_avro_folder_to_csv()` takes one hard-coded `raw_data/v6` folder per date, `sorted()` on filename string, loops a hard-coded `date_list` typed by hand per participant. `SOURCE_FOLDER` and `DESTINATION_FOLDER` are absolute paths on the original analyst's Desktop and in the shipped copy point at **two different participants** (source `P3-<name>`, destination `P4-<different name>`). | Recursive discovery keyed off `config/participants.csv` (`wearable_folder`), sorted by embedded UNIX seconds. No hard-coded dates, no absolute paths, no per-date manual lists. Record every contributing AVRO path in `source_avro_files`. |
| **Timestamp representation** | UNIX **microseconds** as `int64` in the CSV column `unix_timestamp`; converted to float seconds once at load. Windows carry 10-digit UNIX seconds. | UNIX microseconds as float, written through `np.column_stack` with string columns so the whole matrix becomes `<U32`; downstream `2_HRV...` divides by `1e6` to seconds. A second, human-readable local-time string column is written alongside for every sample. | UNIX microseconds `int64` internally for raw samples; UTC `pandas.Timestamp` (tz-aware) for every window boundary. Never a naive timestamp after parsing. |
| **Timezone conversion** | `America/Chicago` hard-coded (single-site study). Low-rate channels get a vectorised local `datetime` string; high-rate channels (BVP, accel) omit it for size/speed. Session log is naive Chicago wall clock, localised then converted to UTC in `utils/segments.py`. | `America/Chicago` hard-coded in **five** places (notebooks 1, 2, 3_hrv_mean_std, 4 commented out, 5). Uses `datetime.utcfromtimestamp(...).replace(tzinfo=utc).astimezone(...)` per sample in a Python loop. Clemson data is processed by the same code, so **Clemson timestamps are rendered in Chicago local time**. | Site-driven tz from `config/participants.csv`. Canonical storage is UTC; local time is a *display* projection computed at report time only. DePaul → `America/Chicago`, Clemson → `America/New_York`. See `docs/timezone_policy.md`. |
| **BVP preprocessing** | Sign flip is not applied; RSD works on the filtered signal and its derivatives. Upsample 64→240 Hz (cubic spline), Butterworth bandpass 0.4–8 Hz order 4, rolling standardisation 0.650 s on PPG/VPG/APG separately. | `PPG = -bvp` (sign flip), then upsample 64→256 Hz cubic spline, bandpass 0.4–8 Hz order 4 (function default is 4.0 Hz but the call passes 8.0), rolling standardisation 0.650 s centered. | Keep the flip decision explicit and documented, not implicit. One preprocessing function, parameters in `config/pipeline.yaml`, identical for both detectors so the ADT-vs-RSD comparison isolates the detector. |
| **Interpolation** | `CubicSpline` to 240 Hz, but **only inside contiguous runs**: `_split_on_gaps()` breaks the series wherever inter-sample spacing exceeds `5/64 s`, so no spline is ever fitted across a watch-off or file-boundary gap. Long segments are additionally processed in 180 s chunks with 5 s overlap. | `CubicSpline` to 256 Hz over `np.arange(min(ts), max(ts), 1/256)` for the whole file at once. No gap detection. Any recording gap inside the file is filled with fabricated signal. | Gap-aware splitting first, then interpolation per contiguous run. Chunked processing for multi-day baselines. Target rate fixed in config (240 or 256 — pick one and record it). |
| **Filtering** | Zero-phase `filtfilt` Butterworth 0.4–8 Hz, order 4, applied per contiguous run/chunk with overlap padding so edge transients fall outside the retained core. | Zero-phase `filtfilt` Butterworth 0.4–8 Hz, order 4, applied to the entire (possibly multi-hour) interpolated array in one call. Edge transients at the file boundary are retained. | Previous-pipeline behaviour: per-run filtering with overlap discard. |
| **Peak detection** | RSD (Murphy thesis): five-point fiducial sequence onset → a-peak → u-peak → b-trough → systolic peak on a PPG−APG composite; IBIs taken between successive **onsets**. `prominence` tunable (tuned per participant in the previous study). | ADT (Shin et al. adaptive thresholding), `ADT_peaks(signal, ts, fs)`; IBIs taken between successive **systolic peaks**. See `docs/adt_audit.md`. | **Primary = ADT** (minimises methodological drift from the original SAR analysis). **Sensitivity = RSD**. Both behind one interface `detect_beats(...) -> beat times`, selected by config. Final choice not yet made — see `docs/open_questions.md`. |
| **IBI artifact rejection** | Two stages in `utils/ibi_validity.py`: (1) physiological bounds 0.40–1.5 s; (2) relative-deviation rule — a beat is invalid if it deviates >20% from a centered rolling median (window 5). Then `invalidate_neighbors()` marks both neighbours of any invalid beat. Nothing is dropped; a boolean `valid` column is carried so rejected beats still break adjacency. | Mateo & Laguna divided-difference rule (`detect_abnormal_beats`, `window_size=300` **beats**, `xi=4.3`, `max_threshold` overridden to 1.0 at the call site), then the abnormal beat *and the one after it* have their IBI set to NaN. Then a one-sided physiological limit: `IBI > 1.15 s` → NaN (and its successor). **No lower bound** — a split beat producing a 0.4 s IBI is kept. | Both rules, in this order: physiological bounds (two-sided), then Mateo–Laguna, then neighbour invalidation. Keep rejected beats in place with a `valid` flag so no successive difference is ever taken across a removed beat. Report `n_total_ibi` and `n_valid_ibi` per window. |
| **RMSSD definition** | `utils/hrv.py`: neurokit2 `nk.hrv_time` on pseudo-R-peak indices reconstructed from the IBI series. Computed **per continuous valid run** inside the window, then pooled as the difference-count-weighted root mean square, so no difference crosses a rejected beat. Units ms. | `np.sqrt(rolling.mean(diff**2))` where `diff = IBI.diff()*1e3`, hand-rolled inside `get_time_domain_HRV`. `pandas` mean skips NaN, so a difference spanning a rejected beat is skipped but a difference spanning a *gap* between valid beats is not distinguished. Units ms. | neurokit2 for the published number, hand-rolled formula retained as a unit-test oracle. Run-aware pooling as in the previous pipeline. |
| **Window construction** | Fixed **non-overlapping** 60 s grid anchored at the segment start (`np.arange(start, end, 60)`); one row per window. | `df.rolling(on="dt", window="60s", center=True, min_periods=1)` at **beat-level resolution** — one row per beat, ~60–100 rows per minute, adjacent rows sharing nearly all their IBIs. **This does not match the manuscript.** See `docs/rmssd_windowing_audit.md`. | True non-overlapping 60 s intervals on a UTC grid. One row = one interval. Beat-level rolling output may be kept as an optional diagnostic artifact, never as the analysis unit. |
| **Minimum beat / coverage requirement** | `MIN_IBIS_PER_WINDOW = 5` valid beats or RMSSD is NaN; `coverage = sum(valid IBI seconds)/60` reported per window; baseline stage additionally requires `coverage >= 0.50`. | `min_periods=1`. A window containing a single successive difference returns RMSSD = |that difference|. No coverage metric anywhere. No minimum beat count. | Require both: `n_valid_ibi >= 5` **and** `coverage >= 0.5` (thresholds in config, sensitivity-tested). Emit the window row with `rmssd_ms = NaN` rather than dropping it, so coverage of the timeline stays auditable. |
| **Motion QC** | `utils/motion.py` reads the Empatica per-minute `accelerometers-std` digital biomarker; `MOTION_THRESHOLD_G = 0.050` excludes high-motion minutes from the baseline; `MOTION_FLOOR_G` detects the sensor floor. | None. Accelerometer is converted to CSV in notebook 1 and never used again. | Per-minute accel SD joined onto every window as `motion_metric`. Used to filter the baseline; carried (not applied) on task windows so the filter can be varied in sensitivity analysis. |
| **Wear detection** | `load_wearing()` reads the `wearing-detection` biomarker; baseline windows below 50% worn are excluded; sensor-floor accel is a second off-wrist signal. | None. | `wear_percentage` on every window from the `wearing-detection` biomarker; baseline requires ≥50%; task windows carry the value. |
| **Baseline calculation** | Stage 4 computes per-participant mean and SD over **motion-, wear-, and coverage-filtered** baseline windows only, and writes the exclusion reason for every excluded window. No time-of-day rule (documented decision). | Two separate, inconsistent notebooks. `3_calculate_mean_std` walks a tree for `*HRV.csv`, concatenates the `RMSSD` column, `describe()` → SD is `ddof=1`. `3_hrv_mean_std` reads `hrv.xlsx` per date, drops `RMSSD == 0`, and computes SD with `np.std` (**`ddof=0`**) in one cell and `pd.Series.std` (`ddof=1`) in another. Participant means/SDs are then **hard-coded as literals** into `4_detect_spike`. No quality filtering at all; baseline is every beat-level row including motion, off-wrist and sleep. | One baseline function, one SD convention (`ddof=1`), quality-filtered inputs, written to `results/baseline_stats.csv` and **read** by the spike stage — never transcribed by hand. |
| **Spike detection** | `utils/spikes.py`: flags windows beyond `mean ± N*SD` for N = 1, 2, 3 in both directions, groups contiguous flagged windows into episodes, reports duration in minutes, n_windows, mean/min/max RMSSD and deviation in SD. NaN windows break continuity. | `4_detect_spike`: `RMSSD < mean - N*SD` only (downward), N = 1, 2, 3; `Spike_Group` via `(x != x.shift()).cumsum()`; `Spike_Duration` = `groupby(...).transform('count')` — a count of **beat-level rows**, not minutes. Mean/SD are literals in a dict. | Previous-pipeline logic on true 60 s windows so episode duration is genuinely in minutes. Both directions retained; the manuscript's direction chosen explicitly. Thresholds swept (previous `7_threshold_sensitivity`). |
| **Participant handling** | Participant IDs are pipeline inputs; per-participant artifacts under `results/{stage}/{pid}_*.csv`; segment bounds from `session_log.csv`. | Participant identity is encoded in absolute Desktop paths and in `if participant == "P3": start_date = ...` blocks. Real names appear in folder paths. Stats dict keys `P1..P4` with two entries commented out. | `config/participants.csv` is the single registry: `participant_id`, `site`, `wearable_folder`, `ema_id`, `timezone`, `robot_delivery`, `analysis_include`, `exclusion_reason`. No participant identity anywhere in code. No real names in paths or outputs. |

## Definite bugs found

### Swetha pipeline

1. **Wrong destination participant in the shipped AVRO converter.** `1_avro_to_csvfile_convertion.ipynb` reads `.../P3-<name>/avro/{date}/DEPAUL3-<device>/raw_data/v6` and writes to `.../P4-<different name>/CSV FILES/{date}`. If executed as saved, P3's data lands in P4's folder. Any downstream file produced from that folder has unverified provenance.
2. **Append-mode conversion is not idempotent.** `mode = 'ab' if append_mode and os.path.exists(file_path)`. Re-running the converter over an existing output directory duplicates every sample. The notebook's own duplicate-checking and in-place-sorting helpers are evidence this occurred.
3. **Cubic spline across recording gaps.** `interpolate_signal` builds one uniform grid from `min(ts)` to `max(ts)` and fits a single `CubicSpline`. Watch-off periods and file-boundary gaps are filled with fabricated waveform, which then gets peaks detected on it.
4. **Rolling window is not the manuscript's non-overlapping window.** Detailed in `docs/rmssd_windowing_audit.md`.
5. **`min_periods=1` admits single-difference RMSSD.** With one valid successive difference in the window, RMSSD equals the absolute value of that one difference. These values enter the baseline mean/SD and the spike test.
6. **No lower physiological IBI bound.** Only `IBI > 1.15 s` is rejected. Split beats (short IBIs) survive and depress RMSSD in exactly the direction the study calls a "spike".
7. **Two mutually inconsistent baseline notebooks.** `3_calculate_mean_std` (`ddof=1`, keeps zeros, reads `*HRV.csv`) vs `3_hrv_mean_std` (drops `RMSSD == 0`, `np.std` `ddof=0` in one cell and `ddof=1` in another, reads `hrv.xlsx`). Which one produced the manuscript numbers is unknown.
8. **Baseline statistics hard-coded into the spike stage.** `participants_stats = {"P1": {"mean": 69.38, "std": 49.10}, ...}` with P2, P3, P4 commented out, while `participant = 'P1'` is fixed. Running the notebook as saved labels every participant's file with P1's baseline.
9. **Column contract broken between stages 4 and 5.** Stage 4 selects `["ts", "Chicago_Timestamp", "RMSSD", "Spike_RMSSD_1SD", ...]` but the `Chicago_Timestamp` block that would create that column is commented out — the selection raises `KeyError`, which the bare `except Exception` swallows and prints, so the stage can report "0 files saved" without failing. Stage 5 then reads `["ts", "RMSSD_60", "Spike_RMSSD_60", "Spike_Group", "Spike_Duration"]`, none of which stage 4 writes.
10. **Stage 5 overwrites its own input.** `5_Timestamp_hrvspike.ipynb` reads `.../2025-02-19/HRV.xlsx`, filters to a 12-minute clock window, and writes back to the same path. The unfiltered file is destroyed. The comment says "3:14 PM to 3:45 PM" while the code uses `time(16,12)`–`time(16,24)`.
11. **`Spike_Duration` counts rows, not minutes.** `transform('count')` over beat-level rows. At ~72 BPM a 1-minute spike reports a duration of ~72.
12. **Clemson data rendered in Chicago local time.** `America/Chicago` is hard-coded in every timestamp conversion, including the loop over `Clemson data/Clemson/Empatica/...`. One hour of offset error for all Clemson local timestamps, which is how EMA responses would be matched to windows.
13. **Module-level constant mutated inside the processing loop.** `SAMPLING_FREQUENCY = NEW_FREQUENCY` inside the per-date loop. Correct only because interpolation is unconditionally on; flipping `DO_INTERPOLATION` to `False` silently filters at the wrong rate.
14. **ADT index-0 initialisation fabricates one interval per file.** See `docs/adt_audit.md`.

### Previous pipeline

1. **`prominence` and `rel_threshold` are tuned per participant and not portable.** They were fitted on five DePaul participants' wrist BVP and there is no reason they transfer to SAR participants or to Clemson hardware. Carrying them over unexamined would be a silent methodological assumption.
2. **`_split_on_gaps` uses `gap_factor / original_fs` with `original_fs` fixed at 64 Hz**, so the gap rule is tied to the sample rate of that study's device. Fine, but must be config-driven here.
3. **`utils/hrv.py` docstring names the window `RMSSD_60` and hard-codes `WINDOW_S = 60`** while `windowed_rmssd` accepts a `window_s` argument — the emitted column name does not follow the argument. A 30 s call still writes a column called `RMSSD_60`.
4. **`America/Chicago` is hard-coded in `avro_to_csv.py`, `motion.py`, and `segments.py`.** Single-site assumption baked into three modules. This is exactly what breaks on a two-site study.
5. **`rmssd_from_ibis` calls `nk.hrv_time` once per continuous run per window.** Correct, but it is a heavy call inside a triple loop; on multi-day baselines this dominates runtime. Worth caching or vectorising before the full SAR run.
